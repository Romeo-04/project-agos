# AGOS — Storyboard Master Plan
### A four-part storyboard for the Zambales flood problem, built on the pattern used by Team Sharksfin (Philippines, HydroLink) — ASEAN DSE's own reference winner.

---

## 0. What we are copying from Sharksfin, and why

Team Sharksfin's storyboard (*"ASEAN's Silent Water Crisis"*, HydroLink) runs 79 pages across four parts. We reverse-engineered its actual page-by-page structure (not just its headline sections) to borrow the mechanics, not the words:

| Part | What Sharksfin actually did | What we take from it |
|---|---|---|
| **Problem** | Opens on a ground-level anecdote (Poblacion, Panglao — cites a named 2024 journal study), then widens to a 10-country ASEAN bar chart (UN-Water data), then runs a repeating "when communities are left out" card per country (Indonesia, Vietnam, Philippines, etc.), then a 5-year UN report timeline showing the problem is old and unsolved, then a table of *current* per-country data gaps | Same interleaving: hook → ASEAN baseline → country-level human toll → gap table → then narrow to Philippines → Zambales → Olongapo |
| **Call to Action** | One-slide pivot: full-bleed atmospheric photo, single icon, and one line reframing the crisis as an *opportunity* ("There is an opportunity to empower rural communities...") | Same pivot shape: not a question, a permission-to-act statement |
| **Solution** | Reveals "HydroLink" by name and tagline, then a Components (Hardware/Software) vs. Features (Data-driven/Participatory) hub diagram, then a hardware pipeline (Sample Intake → Chemical Prep → Visual Capture → Data Analysis), then an explicit SAP callout diagram ("HydroLink's Software" ring literally circles the SAP logo), then one dedicated slide per feature — each with a phone mockup, annotated callouts, a "Specific Synergies" box (stakeholder + benefit), an "SDGs" box (exact indicator codes, e.g. 6.3.2), and a "Specific Targets" box (ASEAN Blueprint paragraph reference) | Same feature-slide template, applied to AGOS's five components (EYE, PULSE, VOICE, PATH, FUND) — plus a Failure & Mitigation layer Sharksfin did not show, which we add as our own differentiator |
| **Business Model** | Pivot slide ("How do we ensure HydroLink's sustainability?"), reveals a B2B2C model, two revenue streams shown one at a time (Hardware Sales, Platform Subscription — explicitly "SAP-powered"), a win-win-win stakeholder box (Gov't/NGOs, Communities, HydroLink), then a 4-phase roadmap with a Step/Action pair per phase and per-phase KPIs, explicitly citing a cross-country model (Malaysia's CEPA approach) as precedent | Same shape, with ASEAN-level *institutions* (not just generic "governments/NGOs") named specifically, since a competition entry that names AHA Centre by name reads as more credible than one that says "regional partners" |

Everything below is written so you can hand each section straight to Claude Design or Claude Code as a build brief.

## PART 3 — SOLUTION
### AGOS, rebuilt around the SAP stack judges are already primed to expect

### 3.1 The technical reality worth knowing before you design this

Sharksfin's software ring literally circles the SAP logo and labels the output layer "HydroLink's Software," feeding a Community Mobile App, a Website/SMS channel, and a "National Water Security Dashboard." This is not a generic "we use SAP" claim — it maps to a real, documented SAP reference architecture that SAP itself publishes: **SAP Build Apps → SAP BTP (integration) → SAP Datasphere (data modeling) → SAP Analytics Cloud (dashboard/story)**. SAP's own sample scenario for this exact pattern is a tank farm with some tanks on automated IoT sensors and others still read manually by a field technician — which is, almost exactly, AGOS's Bucao/Santo Tomas (sensor) vs. Olongapo (currently manual-read bridges) situation. Use this real parallel; it is a stronger, more specific claim than "we'll use SAP Analytics Cloud" alone.

### 3.2 The SAP technology map

| AGOS layer | SAP product | What it does here |
|---|---|---|
| Data collection (sensors + manual entry) | **SAP Build Apps** | Front-end for two data paths: (1) automated sensor pings from Bucao/Santo Tomas, (2) manual water-level entry by Olongapo's OCDRRMO staff at the three bridges, until they're automated too |
| Integration | **SAP BTP (Business Technology Platform)** | Connects sensor feeds + manual entries + PAGASA/NASA POWER rainfall feeds into one pipeline |
| Data modeling | **SAP Datasphere** | Houses the modeled dataset: river level readings, rainfall history, lahar-volume estimates, evacuation records — the single source every dashboard reads from |
| Visualization (competition-mandatory) | **SAP Analytics Cloud (SAC)** | Builds the required storyboard charts, AND powers the live "National-style Water/Flood Security Dashboard" for LGUs |
| Alerting | **SAP Build Apps** (same tool, second app) | The barangay/household-facing mobile app — SMS fallback for low-signal areas |

Build each of these as its own slide, in Sharksfin's exact template: **feature name/category tag (left) → phone or dashboard mockup (center) → three stacked boxes (right): Specific Synergies / SDGs / Specific Targets.** We add a fourth box Sharksfin didn't use: **Failure & Mitigation.**

#### EYE — Satellite & Drone Lahar Scan
- **Category tag:** Predictive
- **Mockup to design:** A SAC-style dashboard screen (desktop, for LGU engineers) showing a river-segment map of Bucao/Santo Tomas, color-coded by estimated remaining lahar volume (green/yellow/red), with a "last scanned" timestamp and a "Request Priority Dredge" button
- **Specific Synergies:**
  - DENR Mines and Geosciences Bureau — receives standardized volume estimates instead of ad hoc surveys
  - Provincial Engineering Office — gets a defensible, data-backed dredging priority list
- **SDGs:** 11.5 (reduce disaster deaths/economic loss) · 9.1 (resilient infrastructure)
- **Specific Targets:** ASEAN Vision 2025 on Disaster Management — Priority Area on risk assessment and monitoring
- **Failure & Mitigation:**
  - *Failure:* Satellite pass frequency too low to catch fast lahar shifts after a single storm → *Mitigation:* Pair satellite scans with drone flyovers triggered automatically whenever a PULSE sensor crosses its warning threshold, so the highest-need moments always get a fresh scan
  - *Failure:* Cloud cover during monsoon blocks optical satellite imagery exactly when it's needed most → *Mitigation:* Use Synthetic Aperture Radar (SAR) satellite sources (e.g., Sentinel-1), which see through cloud cover, as the primary feed during active monsoon windows

#### PULSE — River Sensors
- **Category tag:** Predictive
- **Mockup to design:** A simple IoT sensor device card (hardware spec sheet style, like Sharksfin's "Relevant Components" strip) — solar-powered water-level sensor, LoRa or cellular uplink, mounted on existing bridge infrastructure (Del Rosario, Sta. Rita, Kalaklan bridges are literally already there — no new civil works needed at the Olongapo pilot site)
- **Specific Synergies:**
  - Olongapo City DRRMO — automates what three staff currently read manually
  - DPWH — sensor housing piggybacks on existing bridge maintenance visits, no new access roads needed
- **SDGs:** 11.b (integrated disaster risk management at local level) · 13.1 (strengthen adaptive capacity)
- **Specific Targets:** AADMER Work Programme — early warning systems component
- **Failure & Mitigation:**
  - *Failure:* Sensor damaged or swept away in extreme flow (a real risk — this is exactly the kind of water that destroys infrastructure) → *Mitigation:* Mount sensors above historical maximum flood line using non-contact ultrasonic/radar level sensors, not submerged probes; budget for annual replacement as a consumable, not a one-time capital cost
  - *Failure:* Cellular signal loss during a storm, when it matters most → *Mitigation:* Dual uplink — LoRaWAN mesh between sensors as primary (works without cell towers), cellular as backup for reaching the cloud

#### VOICE — SMS & App Alerts
- **Category tag:** Participatory
- **Mockup to design:** Mirror Sharksfin's exact phone-screen layout (page 38) — color-coded alert screen: "Barangay [X] River Alert — RISING," a status color band (green/yellow/red matching PAGASA's own rainfall warning colors, so residents don't have to learn a new system), a plain-language "What To Do Now" card with two buttons: "Evacuation Route" and "Nearest Center"
- **Specific Synergies:**
  - Local telecom providers (Globe/Smart) — SMS gateway partnership, likely at CSR/reduced-rate terms given disaster-response framing
  - Barangay captains — become the verified local relay, preserving the existing trust chain rather than replacing it
- **SDGs:** 1.5 (resilience of the poor to disasters) · 11.5
- **Specific Targets:** ASEAN Declaration on One ASEAN One Response — community-level preparedness
- **Failure & Mitigation:**
  - *Failure:* Power/cell outage cuts off the exact households most at risk → *Mitigation:* A barangay-level solar-charged siren/light beacon as a zero-connectivity fallback, triggered by the same PULSE threshold — no phone required to know to evacuate
  - *Failure:* Alert fatigue — too many false alarms erode trust (a documented failure mode of early-warning systems everywhere) → *Mitigation:* Three-tier alert language (Watch / Warning / Evacuate Now) instead of binary alert/no-alert, so residents can calibrate response to severity instead of tuning out

#### PATH — Live Route Map
- **Category tag:** Participatory
- **Mockup to design:** A community-editable map screen — barangay officers mark a road/bridge as "Passable / Caution / Impassable" with one tap; residents see a live routed path to the nearest open evacuation center, re-routing automatically if their default route goes red
- **Specific Synergies:**
  - DPWH District Engineering Office — receives crowd-verified road status faster than formal inspection can confirm it
  - Subic Bay Metropolitan Authority — direct relevance, since Olongapo flooding has already cut off the Kalayaan Gate route into the Freeport
- **SDGs:** 11.2 (safe, affordable transport access) · 9.1
- **Specific Targets:** ASEAN Comprehensive Recovery Framework — connectivity and logistics resilience
- **Failure & Mitigation:**
  - *Failure:* Crowd-sourced status can be stale or wrong if no one updates a segment → *Mitigation:* Require a re-confirmation timestamp; a status older than 2 hours auto-downgrades to "Unconfirmed — proceed with caution" rather than showing stale "Passable"
  - *Failure:* Malicious or mistaken false reports → *Mitigation:* Only barangay-verified officer accounts (not the general public) can set status; general residents can only flag/dispute an existing status for officer review

#### FUND — Revenue Link
- **Category tag:** Sustainability (bridges Solution into Business Model)
- **Mockup to design:** A simple LGU-facing dashboard widget: "Lahar-Sand Revenue This Quarter → AGOS Operating Cost This Quarter → Net" bar comparison, showing the self-funding loop transparently
- **Specific Synergies:**
  - Zambales Provincial Treasurer's Office — existing sand-sale revenue gets a transparent, trackable destination
  - Private aggregate buyers — a public dashboard of dredge volume and pricing builds buyer trust in the program's legitimacy
- **SDGs:** 12.2 (sustainable management of natural resources) · 17.17 (public-private partnerships)
- **Specific Targets:** ASEAN Comprehensive Investment Area — infrastructure financing
- **Failure & Mitigation:**
  - *Failure:* Sand-sale revenue fluctuates with construction demand, creating funding gaps in slow quarters → *Mitigation:* Structure as a reserve fund model, not a pass-through — bank surplus in high-demand quarters against low-demand quarters, so sensor uptime never depends on this month's sand price

### 3.5 Ambitious / high-impact features worth including (per your instruction — impact matters more than modesty)

- **Cross-border lahar/monsoon data share with Region III neighbors (Bataan, Tarlac, Pampanga):** since the same August 2026 Orange Rainfall Warning covered all of them, a shared regional dashboard multiplies AGOS's value without multiplying its cost
- **AHA Centre ASEAN Disaster Information Network (ADInet) integration:** push AGOS's Zambales data directly into ADInet, so a Zambales flood shows up in ASEAN's own regional situational awareness feed — this is the single most credible "we understand how ASEAN institutions actually work" move available to a student team
- **Post-disaster parametric micro-insurance trigger:** once a PULSE sensor crosses a defined threshold, auto-trigger a claims process for enrolled households — removes the weeks-long claims-adjustment delay that usually follows a flood

## PART 4 — BUSINESS MODEL AND PLAN

### 4.1 Revenue model — B2B2G (Business-to-Business-to-Government)

Sharksfin used B2B2C (institutions pay, communities receive free). AGOS's real customer is government, not consumers, so the honest model is **B2B2G**: SAP and hardware vendors sell through AGOS, AGOS serves LGUs and national agencies, and the community receives the alert for free.

| # | Stream | Mechanism |
|---|---|---|
| 1 | **Hardware Sales** | One-time fee per sensor unit sold/installed to a Province or City DRRMO, covering manufacturing + installation (mirrors Sharksfin's stream 1 exactly) |
| 2 | **Platform Subscription** | Recurring annual fee per LGU for access to the SAP-powered dashboard, alert routing, and Datasphere-modeled historical record (mirrors Sharksfin's stream 2 exactly) |
| 3 | **Data Insights Licensing** *(new — modeled on Myanmar NEXUS's stream)* | Anonymized, aggregated flood-risk datasets licensed to insurers building parametric flood products, and to academic/research institutions |
| 4 | **Grant & Development Financing** | Capital-expenditure phase (sensor rollout) funded through disaster-risk-reduction grant windows (see 4.2), not through LGU operating budgets, so adoption isn't blocked by year-one cost |

### 4.2 ASEAN-level institutional partnerships (named, not generic)

This is the section a "generic partners" business model usually gets wrong. Name the actual bodies:

| Institution | What it actually does | AGOS's role with it |
|---|---|---|
| **AHA Centre** (ASEAN Coordinating Centre for Humanitarian Assistance on disaster management, Jakarta) | ASEAN's primary disaster coordination body; runs ADInet, deploys ASEAN-ERAT emergency response teams | Feed AGOS's Zambales/Olongapo data into ADInet; a pilot precedent the AHA Centre could point to when discussing member-state early-warning capacity |
| **ACDM** (ASEAN Committee on Disaster Management) | Governing board of the AHA Centre, made up of the heads of each country's National Disaster Management Organisation | Long-term channel for scaling AGOS's model to other member states, the same way Sharksfin's business model explicitly names cross-country consortium roles |
| **NDRRMC / OCD** (Philippines' own National Disaster Risk Reduction and Management Council / Office of Civil Defense) | The Philippines' seat at the ACDM table; already the source of our national-context data | Direct government sponsor and validator at the national level, sitting above the Provincial PDRRMO/OCDRRMO relationship |
| **DELSA / JAIF** (Disaster Emergency Logistics System for ASEAN, funded by the Japan-ASEAN Integration Fund) | An existing, funded ASEAN-Japan disaster-logistics cooperation program | A realistic grant-financing pathway for stream 4 above — this is not a hypothetical funder, it is an active program with a track record |
| **World Bank / ADB (Asian Development Bank)** | Already cited in our Stakes slide for the 6%-of-GDP climate risk projection | Infrastructure financing partner for the FUND component and for scaling sensor rollout beyond the pilot |
| **DENR-MGB, DPWH, PAGASA** | National technical agencies, already integrated into AGOS's own data pipeline | Technical data partners (see the Technology & Partners table in the existing deck) |

### 4.3 Win-win-win framework (mirrors Sharksfin's page 65 exactly)

| Stakeholder | What they receive |
|---|---|
| **LGUs & National Agencies** | A defensible, data-backed early-warning system and dredging-priority tool, funded partly through existing sand-sale revenue, not a new tax line |
| **Communities** | A free, always-on alert that speaks their existing PAGASA color language, with a manual fallback that needs no smartphone |
| **AGOS** | Recurring platform-subscription revenue plus a licensing stream, funding continuous improvement without depending on one-time grants alone |

### 4.4 Implementation roadmap (4 phases, mirrors Sharksfin's page 62 exactly)

| Phase | Timeframe | Step | Action |
|---|---|---|---|
| **1. Engagement & Planning** | Months 1–3 | Assess needs, co-design with Olongapo OCDRRMO (fastest pilot — see deployment plan) | Formal MOU with Olongapo City and Zambales PDRRMO |
| **2. Deployment & Set-up** | Months 4–9 | Convert Olongapo's 3 manual bridge gauges to PULSE sensors; install first 6 Bucao + 4 Santo Tomas sensors | Devices begin collecting data into SAP Datasphere |
| **3. Operation & Uptime** | Months 10–15 | Launch VOICE alerts and PATH route map; SAC dashboard goes live for LGU engineers | Establish a seamless, monitored data stream; first full monsoon-season stress test |
| **4. Scaling & Reporting** | Months 16–24 | Expand to Region III neighbors (Bataan, Tarlac, Pampanga) under the shared regional dashboard; submit first report to AHA Centre's ADInet | Publish first Annual Flood Resilience Report; pursue DELSA/JAIF co-financing for Phase 5 expansion |

### 4.5 KPIs (mirrors Sharksfin's explicit-numbers style — fill in target numbers once your team sets them)

- Number of sensors live and reporting uptime ≥ 99% during monsoon season
- Average alert lead time (minutes/hours between VOICE alert and river reaching evacuation threshold)
- Number of barangays with an active officer account on PATH
- Cubic meters of lahar dredged per quarter, and % change vs. the pre-AGOS baseline (currently ~1% removed since 2020 — this baseline is your easiest KPI to beat)
- LGU platform-subscription renewal rate (proxy for perceived value)
